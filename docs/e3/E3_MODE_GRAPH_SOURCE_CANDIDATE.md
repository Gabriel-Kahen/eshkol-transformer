# E3 in-call mode and graph source candidate

This noninstalled candidate implements the [accepted observation contract](E3_MODE_GRAPH_OBSERVATION_CONTRACT.md)
as one exact E1B test tuple. The independently approved P1 test seam passed
its supported compiled gate. This consumer is **source-only** until its own
supported normal, poisoned, sanitizer and fresh-build gate passes.
No E3 §9 mode, graph, retention or numerical result follows from this source.

`generate-e3-mode-graph-source.py` pins the canonical P1 and E3 roots and
extension, checks the small checked-in E3 test root, and emits two build-private
sources with fixed SHA-256 digests. The original P1 73-slot trusted surface is
untouched. The E3 transform inserts only one preacquire call, one actual-mode
read after P1 enter, and one read after each staged batch immediately before
its first forward role. The P1 reader uses the authentic frame token; an
already allocated cell retains four immediate mode masks and actual graph
event snapshots. No raw M3T slot or P1 shell is inspected.

The native test observer counts entry to real M3 capture, successful
`M3_GRAPH` enrollment, successful root release, and live graph records. The
graph mutant uses a precreated workspace and genuine two-ID M3T input for the
same E3 model. In the window after D2 prepare and before E3 native acquire,
inside the existing outer `m3-call`, it runs the internal workspace begin,
21-role forward schedule, real capture, reset and release. It never calls a
nested public wrapper, swaps models or clears the E3 exclusion. Partial-mutant
errors reset the workspace and release any graph before rethrowing the first
error; an impossible cleanup failure fail-stops.

The missed-child variant skips exactly child 2's enter write and narrowly
allows that same child to remain train during the test-only entered snapshot
check. This keeps authentic restoration possible so the saved *in-call* mask
assertion can kill the mutant after cleanup. A separate enter-write-only
variant keeps the original snapshot check and must fail-stop at restoration;
its process exit is a control, not the in-call observation proof. Both variants
leave normal P1 source bytes and canonical owner checks unchanged.

The driver reuses one model, D2 dataset, E3 frame and destinations across
success, a later injected D2 read fault, and same-authority retry. It checks
actual mixed17 restoration, all model parameter and gradient words and
metadata, initializer state, cursor, publication bits and counters, and zero
live graph owners. The existing test-only retention observer checks that live
I2 tensors, parameters, views and plans, E3 frames, D2 datasets, batches,
borrows, owned allocations and FDs return to the setup baseline after each
call; I2 borrow begin/end event deltas must balance. It prints recorded masks
and event deltas only after each
guarded call. The verifier requires four authentic success/retry observations,
the fault observation, and zero normal graph events; the compiled mutants must
be rejected specifically by their in-call mask or enrollment deltas.

The exact tuple has separate root/bridge, generated-source normalization,
source/native closure and export/string/defined/undefined inventories, and
native test flags. Existing canonical, diagnostic, installed, retention and
numerical package sources and inventories are unchanged. Supported emitted
inventory comparison and actual runtime behavior are pending; an unexpected
emitted dependency is a gate failure requiring evidence, not an allowlist
waiver.

The candidate composes the independently reviewed numerical sanitizer fix:
the relocatable link materializes Clang ASan's COMMON registration cell only
for an authenticated noninstalled sanitized E3 tuple before unchanged symbol
localization and export checks. Canonical and normal link flags stay unchanged.
