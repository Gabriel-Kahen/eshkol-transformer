# Public fresh-process resume witness

This bounded test uses the installed `transformer.*` facades and the same
localized TR3 aggregate as the ordinary public caller. Its only extra linked
object, `tests/tr3_public_installed/resume_bits.c`, reads the physical binary32
bits of public metrics; it cannot construct or mutate trainer state. No private
trainer, checkpoint, dataset, model, or optimizer operation is called by the
Scheme caller.

The combined train-interrupt candidate extends the reviewed step witness. For
each accumulation count `A=1,2,3`, the gate starts four OS processes:

1. `baseline` makes four public `trainer-step!` updates, saving a public
   `trainer-state` through `checkpoint-save!` after each update.
2. `train-baseline` makes four updates in one uninterrupted two-argument
   `trainer-train!` call and saves its final public C2 state.
3. `producer` enters the three-argument `trainer-train!` with a four-update
   limit. After update `K=1`, its callback publishes a ready marker. The
   external shell driver observes ready, creates the request marker, and the
   callback records an acknowledgement before returning `#t`. Both sides
   bound their waits. The returned summary is checked as one committed update
   before the public state is saved.
4. `receiver` constructs fresh compatible operands, verifies that a corrupted
   checkpoint fails `checkpoint-load`, verifies that the loaded valid owner
   fails `trainer-load-state!` against a different run-seed configuration, then
   restores its original trainer and makes updates 2 through 4 with public
   one-update `trainer-train!` calls.

The script compares the producer checkpoint and the immediately restored
checkpoint with baseline update 1, then each resumed checkpoint with its
baseline counterpart. The uninterrupted train checkpoint must equal baseline
update 4. It also compares the four one-update train summary `loss` and
`mask-weight` f32 bit patterns and token counts with independent public step
metrics. The uninterrupted train summary must report four updates and the
same total token count as the step path. The callback acknowledgement is
observational caller state and does not enter C2.
The linked step caller also checks that reentrant public release, step,
train, state, and load calls reject during polling and preserve the cursor.
The producer repeats state and load rejection; its exact K checkpoint
comparison checks full receiver preservation after those attempts.
The installed facade does not yet provide `trainer-evaluate!`; its polling
guard remains a composition requirement for the evaluation package.
The public `optimizer-create` receives the accepted O2 linear schedule
`(linear 2 6 "3dcccccd")`: two warmup updates, six total updates, and a
binary32 minimum ratio of 0.1. Successive baseline C2 files differ, and all
four public loss words differ for each accumulation profile. Against the
earlier sealed constant-schedule run on the same production source, update 1
has the same loss word in all three profiles; updates 2 through 4 differ in
all three. This differential shows that the schedule change affects the later
public numerical trajectory, while the uninterrupted and resumed linear paths
remain exactly equal.
Pre/post checkpoint bytes prove that the corruption and configuration-mismatch
attempts preserve their respective receivers. The two-row finite D2 fixture
forces the resumed suffix through end-of-stream; `A=1` and `A=3` have unequal
active-token counts across updates. Every checkpoint is generated by the
accepted C2 public SAVE path from an owned trainer snapshot, and the producer
checkpoint is read through the public capability-gated LOAD path.

The accepted `trainer-state`/C2 format contains parameters, optimizer moments,
scheduler, RNG, both D2 cursors, config, versions, and counters. Canonical C2
byte equality checks the complete serialized state at every continuation
point. The public surface has no separate accessors for moments, effective
learning rate, RNG words, epoch-start cursor, or epoch counter, so this gate
does not independently inspect those fields. A separate reviewed private
factor gate directly observed next-update factors `0.5, 1, 0.775, 0.55` and
effective binary32 rate words `3d4ccccd, 3dcccccd, 3d9eb852, 3d6147af`
for the same O2 schedule; its evidence is
`tr3-fresh-lr-fe9-5a9a0bd-20260928/SHA256SUMS` (seal SHA-256
`2d1e33dd3bb207ae0333680b9fb61e3565fac9712141d33fab33a4eaa95b915f`).
The accepted fixed trainer profile has no dropout: training RNG low/high
counters must remain zero, and a nonzero counter is rejected on restore.
There is no authentic public fixed-profile run that advances RNG, so the
combined candidate can prove preservation of that zero state, not continuation after
RNG consumption. The combined train-interrupt gate remains unrun pending the
local heavy slot and independent review. The existing installed step
caller separately injects early, mid, precommit, and rewind failures and
checks public rollback/retry; this fresh-process witness adds corrupted-load
and mismatched-restore preservation.
