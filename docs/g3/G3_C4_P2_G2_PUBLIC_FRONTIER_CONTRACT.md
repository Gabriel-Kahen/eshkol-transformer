## Conditional public G2 boundary

A future public G2 candidate must first receive independent acceptance of a fixed C4 profile and EOS-policy contract. It must preserve the existing C2 and C4 P2/G1 profile admissions, model/input provenance, error order and package ownership. The exact proposed public profile value is **not decided here**; adding one is not authorized by this guard. The only source-grounded fixed request is the private C4 `(P,max G,N)=(2,2,1)` CPU-f32/V256 route with an owned P2 input. Its successful terminal has either one emitted ID and cache three (first EOS), or two IDs and cache four. A public return cannot occur until it has a separately reviewed terminal-aware owner adapter for all five existing output accessors and three releases. The ID accessor must produce a genuine independently owned CPU I1 of logical shape `[1]` or `[2]`; it must never expose the unused physical slot. Text must be an exact detached one- or two-byte copy of authenticated T1 carriers. Length/cache results and RNG owner must reflect the native terminal snapshot, and releases must authenticate original registry authority and commit native success before tombstoning Scheme owners. Clones must survive source-output release and generator close. Private `clone_copy_v1` proves copied bytes only; any public rank/device/element access to kind 9 needs a separately reviewed typed accessor or bridge. No opaque pointer cast or invented native ABI is permitted.

The smallest eventual source composition is one package-root load of the accepted private terminal stack, exact C4 public create/generate routing for the accepted profile, and terminal-specific branches of existing C4 output/tensor/RNG accessors and releases. It is not an edit to the P2/G1 scalar path or a fallback to G3-T/C2. The public E1 boundary must preserve invoked-operation errors, wrong-kind versus dead-owner order, bounded data-only details and cause `#f`; malformed storage/device categories require reviewed source proof, not guessed translation. Data-only continuation, persistence, N>1 and CLI3 remain separate gates.

## Negative source guard and exit gate

The byte pins intentionally fail closed on *any* change to the named public source or manifests: a later implementation must replace/update this guard only with an independently reviewed public contract and exact source/test evidence. The guard itself proves no runtime behavior.
