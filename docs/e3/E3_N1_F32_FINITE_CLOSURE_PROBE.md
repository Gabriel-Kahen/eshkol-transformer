# E3 N1 f32 finite synthetic closure probe

Status: **synthetic diagnostic only; §9 and real-read gates HOLD**.
`tests/e3_private/e3_n1_finite_closure.py` exercises one prerequisite from the
[protected attempt boundary](E3_N1_F32_ATTEMPT_BOUNDARY.md): identify and reap
a detached pipe holder after its direct leader exits. It reads no f32 request,
OCI byte or Docker store, creates no production capture, and changes neither
`CAPTURE_RUN_ENABLED = False` nor `REVIEWED_CAPTURE_SHA256 = None`.

An isolated controller installs Linux `PR_SET_CHILD_SUBREAPER` and a libseccomp
network-syscall deny filter before it launches a fixed Python actor. It fails
HOLD before launch if `CLOCK_BOOTTIME`, `wait4`, pidfds, subreaper or the filter
cannot be established. The leader's only input is a one-byte start handshake;
it generates `L`, forks a holder, and exits. The holder starts a new session,
reports its PID, then waits for an ACK; the controller opens its pidfd before
allowing it to proceed. A missing pidfd or expired deadline closes the ACK
pipe, so the fixed holder exits without entering the timed work. The holder
verifies inherited socket creation is denied, holds the
stdout/stderr pipes briefly, writes `NG`, and exits. The controller pins both
actors with pidfds, observes both `wait4` exit usages, and checks both pipe
EOFs. The late mode asks the holder to outlast a short test deadline; the
controller sends `SIGKILL` through the holder's pidfd and then reaps it; the
test requires the holder's signal exit status. It
never signals a numeric process group after the leader is reaped. The outer
test obtains the controller's own `wait4` peak. Missing setup capabilities
cause a pre-launch HOLD; a runtime pidfd acquisition failure remains HOLD
after launch and closes the holder's ACK. Capability-dependent tests are
explicitly skipped when setup is unsupported, not counted as exercised
closure.

This is a new closure diagnostic beyond the earlier held-pipe regression:
that regression deliberately left the escaped holder outside its measurement
and only proved that a reused numeric PGID was not signaled. Here, for the
fixed generated two-actor program, the adopted holder's stable identity,
resource usage, exit and inherited-pipe EOF are directly observed. A stalled
unreaped actor or missing EOF remains `closure-uncertain` HOLD after bounded
cleanup; a signal request is never treated as verified cessation. Exceptional
or uninterruptible actors may still outlive the diagnostic controller; it is
not a cleanup guarantee. Every
record still has `status=HOLD` and `resource_proof=HOLD`. A subreaper cannot
prove that an unlisted process did not migrate, escape, or inherit a pipe;
there is no private cgroup, source pin, distinct-UID custody, receipt, seal,
whole-procedure interval, or current-RSS proof. The 30-second and
268,435,456-byte **current RSS** limits are unchanged; the short seconds
argument only narrows synthetic test time.

Next gate: review and test a frozen finite actor graph launched directly into

generated bytes. Unsupported confinement or custody must remain HOLD. No
