# E3 retention read-failure allocation audit (diagnostic only)

The independently reviewed `ef126033` complete-E3 fault/control pair measured a fault-only +2,360 root-arena-used change during the failed evaluator call, unchanged through retry. The independently reviewed `8fec18f` direct-D2 pair measured +2,288 under the same 512 completed E3-call prefix and injected exact-read stage; four paired controls were flat. The 72-byte difference is a difference between two call contexts, **not** an identified object or an E3 allocation count. Neither diagnostic passes complete-call retention.

## Source path

- `internal/d2/lib/d2_dataset.esk`: `d2-native-exact-read` failure becomes a typed `io` `token-dataset-next-batch` error carrying `d2-exact-read` domain, `binary-read` code and errno message. `d2-with-shard-region` calls `region-close region caught`, stores the promoted result into the dataset-owned `state[11]` escape cell, and raises that value. The retained compiled private IR contains `eshkol_region_close_builtin(... keeps, 1)` followed by a store of the promoted value into `escape`; this authenticates the executed compilation path, but not which individual allocations account for the bytes.
- `native/e3_private_extension.esk`: stage 5 catches D2's failure, classifies it via `e3-note-caught-error!`, chooses a prebuilt stage/category error from `e3-error-table`, aborts/restores the frame and raises the fixed E3 error after `m3-call`. M3's boundary has a separate rethrow path for exceptions escaping its body; this source alone does not prove that path incurred the 72-byte difference in the measured case.
- `tests/e3_private/retention_arena_diagnostic_driver.esk`: the new, separate `diagnose-d2-map` phase samples root arena at catch, again after typed-error and escape-cell checks, immediately after stage-5 mapping, after call, after checks and after a genuine retry. The adjacent pre-map/post-map samples bound only the mapper call. It also checks that the caught D2 error is the value in the dataset escape cell, that the fixed E3 error table entry was selected, that cursor and D2 live-batch/borrow counters are preserved, and that the E3 retry still matches its calibrated region budget. Fresh `d2-fault` and `d2-control` processes are the nearest controls. No production source or original report assertion changes in this candidate.

## Repair decision gate

A first production candidate, **only after the compiled probe and independent review establish the escape-cell mechanism**, would keep the promoted D2 error in an invocation-local cell in the caller region rather than the dataset-lifetime `state[11]` cell. It must preserve the exact typed category, operation, source domain/code/errno, native cleanup, cursor, no live batch/borrow, and same-authority retry. A matched direct-D2 fault/control and full-E3 fault/control gate must then demonstrate flat root arena under normal, poisoned and sanitized profiles; source reasoning or clearing `state[11]` after a monotone root allocation is not enough. If the mapper probe does not explain the 72-byte difference, a separate E3 boundary observation is required before changing E3 or M3. No production repair has been made here.
