# Private diagnostic-C2 G3 creation companion

The source-only private entry is
`g3r-generator-create-from-sources(model, original-x1, t2,
generation-config, dataset, optimizer)`. It keeps
`g3t-generator-create(model,t2,generation-config)` unchanged. The private
root loads the accepted CLI3 T2-to-T1 bridge, D2 creation lineage, and M3/X1
creation lineage before this leaf. A future package must include the native
G3/M3/O2/D2 objects, `ET_G3R_SAME_OWNER_SAVE_PRIVATE`, and the D2 idle
preflight under `ET_TR3_C_D2_RESTORE`; no package or symbol inventory is
claimed from this source check.

Only a model created with the exact original resolved X1 shell and a dataset
opened with the exact original T2 shell can enter the companion. The O2
optimizer must still own the model's fourteen handles in order. The wrapper
does not require zero completed updates or a zero D2 cursor. It preallocates
the companion row, issuer snapshot, error cell, and next list before the fixed
G3 constructor. The constructor's registered shell is not returned until
native O2 begin/check/end drains, the original graph rechecks, and the
allocation-free companion publication finishes.

The native bridge exports only scalar pointer/i64 calls to Eshkol. A failed
bridge call copies its four-word first error before cleanup. Failed
construction genuinely closes the unreturned G3 shell; uncertain close
stops the process. The lexical completed list retains at most 64 rows; G3
companion retirement is not implemented. The existing public/ordinary G3
entry does not gain lineage. Source-state controls do not prove generated
Eshkol no-reentry or native package behavior.

Checkpoint C2 bytes and pair publication, post-prefill SAVE, cold LOAD, and
resumed generation remain separate gates.
