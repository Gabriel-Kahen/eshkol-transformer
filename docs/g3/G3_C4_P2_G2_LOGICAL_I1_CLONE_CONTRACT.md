Status: **independently reviewed prerequisite contract; repository integration and source implementation remain pending. No public export is authorized.** Source basis: independently accepted native terminal `aae70bb57d597e13c1469fc02b7c655cd40226f5`/tree `01d1e855daed2b2e7bb99485e79e39ebe1cf99b3`, with its accepted 62-file fe9/f31 seal `2e6a74108fa55d4f440661b0322317e9374c3daf0dad6a25da3059700f817d6f`. This leaf is a prerequisite for the separate same-registry Eshkol terminal composer and detached result adapter. It is not a public G2 output API or a continuation format. The native terminal implementation is in [PR #184](https://github.com/Gabriel-Kahen/eshkol-transformer/pull/184); its exact reviewed source and supported gate are accepted, while hosted checks and merge remain pending. ## Why a separate owner is required

The terminal output retains physical dense CPU-i64 `I1[2]` and a native terminal marker but exposes logical length one or two (`src/eshkol_transformer/g3c4_model_owner.c:1668-1708,8344-8471`). The first-EOS second physical slot is zero, not an emitted ID. Native `terminal_snapshot_v1` gives a detached eight-word value descriptor, not an I1 owner (`:8502-8570`). Current C4 `result_tensor_create_v1(kind,value)` creates only scalar `[1]` I1 and hardcodes `length=1/cache=3` (`:8608-8644`); its existing public Eshkol adapter assumes this (`native/g3c4_public_output_adapter_extension.esk:74-132`). The established G3T pattern instead derives clone shape from logical length, copies only those I1 words, enrolls a separate owner, and rejects release while borrowed (`src/eshkol_transformer/g3t_transport.c:837-852,1037-1091`). Eshkol's G3T wrapper enrolls the returned native owner in a typed registry entry and returns `(list shell)`, with cleanup on failed publication (`native/g3t_ids_owner_extension.esk:1-44`).

## Exact proposed private ABI

Add **only under** `ET_G3C4_P2_G2_TERMINAL_IDS_CLONE_PRIVATE`, which requires `ET_G3C4_P2_G2_TERMINAL_PRIVATE`, `ET_G3C4_OUTPUT_RESERVATION_PRIVATE` and the current M3/I1 owner checks, in `src/eshkol_transformer/g3c4_context_internal.h` and `src/eshkol_transformer/g3c4_model_owner.c`:

```c
void *et_g3c4_private_p2g2_terminal_ids_clone_v1(void *terminal_output);
int64_t et_g3c4_private_p2g2_terminal_ids_clone_copy_v1(
    void *clone, int64_t expected_length,
    void *destination_header, int64_t destination_bytes);
int64_t et_g3c4_private_p2g2_terminal_ids_clone_release_v1(void *clone);
```

These names/signatures are **proposals**, not existing functions. The caller passes no ID, RNG, cache, policy or authoritative logical count. `expected_length` on copy is a comparison against the clone's immutable native fact, never permission to change its shape. For Eshkol `ptr`, `destination_header` addresses the complete bytevector header, not its payload. A separate copy accessor is inseparable from the opaque clone ABI: without it the Eshkol wrapper can carry a native pointer but cannot independently read the detached logical I1 payload and verify its shape/content after the source is released. This accessor copies values; it never exposes I1 storage or grants a borrow.

**Allocation-extent split:** a raw `destination_header` pointer, length header and `destination_bytes` integer cannot prove that Eshkol allocated the complete span. Before passing `ptr`, the same-registry adapter must reauthenticate the *original* destination bytevector's exact identity and allocation-time anchor, require `bytevector?`, `bytevector-length == 8 * expected_length`, and establish the complete header-plus-payload extent `16` or `24` from that original allocation. The bytevector may not be substituted by an equal-length object or a mutable record slot. The native entry can check only its readable pointer range, alignment, declared length, exact passed extent and full native-owned-storage aliases; it must not claim to establish Eshkol backing allocation or tokenizer provenance. Recheck original identity and bytes after any fallible Eshkol callback, and keep the destination private until copy and comparison succeed.

Reserve source-private transport kind **9** (the current C4 kinds are input 2, output 4, scalar result 5–7 and RNG 8 at `g3c4_model_owner.c:990-1020`) and a distinct terminal-clone magic `UINT64_C(0x4733433454494431)` (`G3C4TID1`). Its private record contains the common transport header, owned `et_i64_tensor *ids`, and immutable `int64_t logical_length`. Registered LIVE requires kind 9, this magic, idle transport, non-null dense CPU-i64 rank-one storage with exact shape `[logical_length]`, contiguous eight-byte stride, `logical_length` exactly 1 or 2, and IDs in `0..255`. Registered DEAD requires null tensor and zero length. Keep kind-9 admission separate from the scalar result admission range 5–7 and from the public transport/result adapter. The feature must compile with terminal alone; it cannot quietly require `ET_G3C4_P2_G1_PUBLIC_RESULT_PRIVATE`.

**Full-record alias dispatch is inseparable from kind 9.** The current `et_g3c4_transport_record_bytes` switch (`g3c4_model_owner.c:6796-6818`) defaults unknown kinds to `sizeof(header)`. Add an explicit feature-guarded kind-9 case returning `sizeof(et_g3c4_terminal_ids_clone_internal)` for **LIVE and DEAD** registered clone records. Otherwise a pointer into the clone's `ids` or `logical_length` control tail would pass current header-only overlap checks. All existing C4 carrier alias walkers that call this size helper—output-decode (`:6824-6849`), first/second-frame and terminal raw (`:6853-6885,6928,7108,8279`), P2/G1 copyout (`:7488-7518`), and terminal snapshot (`:8473-8500`)—must reject every overlapping byte of that full control record. The new clone-copy walker must do the same, and must also reject live I1 control, shape/stride metadata, element data and borrow storage through the existing I1 overlap query, alongside f32, model and A2 storage. Keep alias rejection before dereferencing a claimed destination header or writing diagnostics to an aliased span. Test an aligned interior pointer in the control tail, including after clone release; a header-only test would miss this regression.

## Clone operation and failure atomicity

Registry-lookup and authenticate the supplied output *before* dereference. Require the distinct detached terminal marker, no parent, original capacity two/prompt two, readiness all one, logical `length=1/cache=3` or `length=2/cache=4`, valid four-word final RNG, and genuine live source I1. Reject pending, P2/G1-published, dead, foreign and forged output even if values match. Preflight `et_m3_private_i64_unborrowed_v1` so a held genuine I1 lease rejects without any clone allocation and can be released for retry. A balanced source borrow must verify rank one, exact physical `[2]`, dense CPU-i64 metadata/16 bytes, aligned data, and both actual IDs; ID0 is `0..255`, ID1 is `0` for G1 or `0..255` for G2. Copy only the first `logical_length` words into native stack scratch, then end the borrow. No caller bytes influence the clone.

Allocate a fresh kind-9 record and a fresh dense CPU-i64 `[logical_length]`; copy the native scratch prefix into it. Every fallible borrow, allocation, tensor create/copy and view/check path must clean up its own resources, preserve the first error, and leave the source, registry, output ID bytes and clone-live count unchanged. After fallible work, reauthenticate source registration/terminal facts and a fresh balanced source view against the original copied IDs, and authenticate the new tensor's shape/data. Only then enroll the new record and return its pointer. That final enrollment is the publication boundary; an impossible failure afterward is fail-stop. A successful clone has no parent or link to the terminal output. Releasing the source afterward leaves the clone's IDs and shape intact. Two clone calls yield distinct independently releasable owners.

`clone_copy_v1` first registry-authenticates only kind-9 LIVE clones. It accepts `expected_length` equal to the actual native logical length and an aligned pointer whose readable header declares exactly `8 * expected_length` payload bytes, with passed total extent `8 + 8 * expected_length` (`16` or `24`). The Eshkol caller proves the *allocation* as specified above; the native function does not. Validate pointer range and full overlap against C4 clone controls, model, I1, f32 and A2 owned storage *before* reading/writing caller bytes. Borrow the clone I1, verify `[expected_length]` dense CPU-i64 and actual `0..255` values, encode them little-endian in private scratch, end the genuine borrow, then reauthenticate clone/header/aliases. Write only the exact payload once. Wrong length, malformed/aliased destination, held clone lease, changed owner, or any borrow failure leaves the entire destination header and payload byte-identical. The source terminal output need not remain live. This bounded copied access lets a private Eshkol adapter check `(list shell)` contents against the authenticated terminal snapshot and T1 raw text without projecting the unused G1 slot.

`clone_release_v1` admits registered kind-9 LIVE or DEAD only. DEAD same-owner release is idempotent; forged, stale, other-kind and cross-owner handles reject without touching any owner. A LIVE clone must have authentic shape/storage and pass `et_m3_private_i64_unborrowed_v1` before mutation. A held I1 lease rejects with the owner still LIVE and allows release/retry. Destroy its I1, null the tensor, zero logical length and mark the record DEAD; an impossible destroy failure after preflight is fail-stop. Its record remains registered as a tombstone for exact repeated release. Neither clone release nor source release mutates the other.

## Eshkol adapter boundary and proof

A separately reviewed private same-aggregate adapter may preallocate a typed `terminal-ids` shell/entry/ledger and the exact readback bytevector, then capture original allocation-time identities in a separate immutable anchor before any native clone/copy call. It authenticates the independently live terminal output shell and its surviving anchor, calls the native clone, checks that the original readback bytevector still has the exact allocated `16` or `24` header-plus-payload extent, and only then passes its `ptr` and matching extent to `clone_copy_v1` with expected count from the terminal snapshot. It must reauthenticate the original bytevector, output shell and clone entry after every recoverable operation, compare both logical IDs with that native snapshot and exact T1 raw bytes before publishing `(list shell)`, and reject equal-length/paired substitutions of shell, record, bytevector or native handle. On any prepublication failure it releases the exact created clone and tombstones the pending entry. The published private owner retains native pointer, logical count and original shell/record identity, and routes only to the new copy/release entries. This does **not** widen the installed G3-G public dispatch, scalar C4 P2/G1 constructor or public tensor release. If another production consumer requires rank/device/element access rather than this copy contract, that is an additional private accessor prerequisite for review, not license to cast the opaque pointer to I1.

Native normal/repeat/ASan+UBSan+LSan proof must include authentic first-EOS G1 and two-token G2 terminal owners; bitwise clone parity/shape and G1 zero-slot exclusion; source release before clone copy; two independent clones; repeated exact release; held source/clone I1 leases with repair/retry; forged, stale, wrong-kind, P2/G1, pending and dead owners; every allocation/borrow/copy cut with error preservation and unchanged source/destination/registry; full live/dead clone control-tail, metadata, I1, f32, model and A2 alias checks across **all** old and new carrier walkers; and private feature-off/symbol/macro boundaries with P2/G1/terminal predecessor gates. A compiled same-registry Eshkol adapter must separately prove original bytevector allocation/extent/identity, equal-length substitution rejection, typed shell identity, copy access, T1 parity and release. No proof here authorizes a public G2 or data-only continuation claim.
