# E3 idle real-model control contract

Status: approved design, repository integration pending; no implementation or compiled proof. Basis: numerical source `0476fe14ad3dc647655e539b8795b3b780f0774c` / tree `8f03d1e5febe89c02db7122ef9de4374ff1cfa5e`. The proposed control uses existing I2/M3 APIs only and adds no native setter or public ABI.

## Available, authentic route

The registered fixed M3 model exposes `module-parameters`, `parameter-tree-paths`, `parameter-tree-handle`, `parameter-tree-tie-groups`, handle shape/dtype/device and the trusted `parameter-handle-tensor-internal` (`internal/p1/lib/transformer/module.esk:2740–2792`). M3 registers 14 distinct parameter handles and one extra `token_embedding/weight` path tied by `eq?` to `head/weight`; its exact schedule is in `native/m3t_transport_extension.esk:307–325,367–392,430–453` and agrees with the independent shape table in `tests/m3/reference.py:36–52`. The observed tree must have 15 paths, exactly this one tie group, and 14 unique live CPU/f32 parameter carriers. Duplicate the *path lookup*, never the tied destination in a copy batch.

`i2-checkpoint-decode` accepts a request `#(payload 'parameter shape 'f32 'cpu 'dense-row-major-contiguous operation #f)` and returns its owned-clone I2 carrier in slot 7 (`native/i2_wave2_root.esk:503–555`); the native decoder creates/copies real f32 storage (`native/i2_wave2_package_bridge.c:770–883`). For each unique handle, decode an exact little-endian all-`0x00000000` f32 payload of `4 × product(shape)` bytes. Use its actual `parameter-handle-shape` as the requested geometry, after verifying the independent fixed schedule; never substitute a manufactured logit, fixture carrier, raw owner pointer, or new setter.

Build 14 `#(destination-carrier owned-clone 'parameter)` assignments, where each destination is the carrier returned by `parameter-handle-tensor-internal` for its authentic handle. `i2-prepare-load #(assignments operation)` authenticates carriers and delegates full-batch shape, alias, borrow and pin preflight. Its actual return is a **one-element vector whose slot 0 is the three-slot tagged plan** (`native/i2_wave2_root.esk:330–383`). Take precisely that returned inner plan via `vector-ref`; pass that same object to `i2-commit-load!`, never the outer vector or a manufactured plan (`native/i2_wave2_root.esk:385–399`). Native prepare pins all 14 sources and destinations; native successful commit copies all 14 and releases the native plan/pins, after which the Eshkol wrapper marks the inner plan consumed. Release each successfully decoded source with `i2-release-owned! #(carrier 'parameter operation #f)` after completed commit (and on failures **before** successful prepare), exactly once, without releasing destination owners.

The native builder's abort is invoked inside the I2 prepare guard on its own exceptions, including a failed result-envelope allocation after native prepare; it is not a reviewed caller-facing abort for a successfully returned plan (`native/i2_wave2_root.esk:341–352`; `native/i2_wave2_package_bridge.c:1005–1032`). Therefore the driver has **no recoverable injection/check/cleanup branch between successful `i2-prepare-load` and completed `i2-commit-load!`**. It must immediately unwrap and commit, without calling observers or allocating auxiliary test records in that interval. Native commit is documented full-write and nonallocating/nonraising after successful prepare, but the Eshkol wrapper still calls native, checks status, mutates plan slots and returns; its complete generated AOT raise/allocation behavior has not yet been independently audited. A malformed returned envelope, commit failure or post-native wrapper defect is fail-stop/internal, never an ordinary atomic rollback test. Recoverable test cuts go before prepare or after completed commit; source-release failures after commit also cannot be labeled unchanged-model rollback.

## Closed scenario and ordering

Add a *separate noninstalled* zero-model driver entry and bridge signature, with its own exact source/object/import manifests and test guards. The existing `e3-test-run` and two-field scenario `#(packing? skipped-batches)` stay byte-for-byte compatible (`tests/e3_private/driver.esk:49–81,128–151`). A fresh zero fixture constructor must: resolve the fixed config, create byte tokenizer and authentic M3 seed-1729 model; immediately retain that sealed model in a rooted test owner; verify exact tree metadata and unique owners; decode and prepare/commit all zero parameters **while the model is idle and before `e3-frame-bind!`**; release sources; create four real I2 scalar destinations; bind the E3 frame; open genuine D2 corpus and evaluate. Never mutate a cached already-bound frame or retarget its owner. On prebind constructor failure, release successfully decoded sources and created destinations and leave no frame bound. The source exposes no reviewed postconstruction M3 model-release API (`native/m3t_transport_extension.esk:395–478`): retain the model root for a bounded retry in the same process, or run constructor-failure cases in isolated processes and let process lifetime own it. Do **not** claim a complete model unwind or leak-free repeated fresh-model failure loop. Use a new model per successful controlled case unless reuse is independently shown safe.

The 14 independent shape rows are: attention K/O/Q/V `(4 4)` each; FFN down `(4 8)`, up `(8 4)`; block norm1 bias/weight and norm2 bias/weight `(4)` each; tied head `(256 4)`; final norm bias/weight `(4)` each; position embedding `(2 4)`. Total parameter storage is 1,184 f32 values / 4,736 bytes, counted once for the tie. Verify exact sorted names, shapes, f32/cpu/dense layout, live registry identities, single tie group, zero payload length, and zero parameter bytes after commit; all other module metadata and modes must be unchanged by the load. Model initializer successor remains `(1 1729 290 0)` and the supplied seed state `(1 1729 0 0)` (`tests/m3t/public_runtime.esk:109–130`); capture typed RNG state separately and require unchanged bits. The load must neither initialize another model nor consume RNG.

## Genuine forward and oracle witnesses

The zero values flow through the real M3 graph: token/position embeddings, both affine norms, Q/K/V, attention, FFN, final norm and tied head each yield +0 finite outputs. Thus all 256 real logits per active position are zero, and the lowest-index tie winner is token 0. Independently construct all 14 zero tensors in pinned development-only PyTorch and run `tests/e3_reference/reference.py:role_trace` plus `tests/m3/reference.py:forward`, asserting both mathematical graphs agree. Freeze role/logit bits and final CE/global outputs using the existing transcript schema; do not create logits directly in the E3 runner. Genuine D1/D2 byte corpora with active next targets all 0 versus all nonzero then distinguish all-correct from all-wrong with the same zero model; mixed targets and a one-valid-token padded batch test count and denominator. For each observed run compare active token IDs/masks, 21 role observations, logits, per-batch loss/count/correct, global aggregate, all four destination bits, both counters and cursor before/after against the independent reference. The expected CE is `log(256)` and PPL near 256 under the existing specified tolerances, not a made-up binary32 literal. The seeded nonuniform baseline remains a separate control for target offset and other numerical mutants; uniform-only output cannot kill those mutants.

## Required negatives and state observations

Before any write, reject a missing/foreign/stale handle; unexpected path, tie or metadata; duplicate tied destination; source/destination alias; malformed decoder request; wrong byte count, rank, extent or f32 geometry; wrong kind/role; forged/released source; active borrow or plan pin; and allocation failure during decode or before the prepare call. On each recoverable **preprepare** failure, compare all 14 original parameter byte images, tie identities, gradient presence/bytes, model modes, initializer successor, typed RNG bits and all existing destination/cursor state; release every owned source and show no live plan/pin/borrow leaks. Test the I2 prepare guard's own pin release on a thrown preparation in a focused I2 test, not as an injected E3-control interval. A prepared plan is one-shot: a second commit/reuse must reject without changing the loaded model, tested only after the first commit has completed. Parameter loading itself must leave gradient state unchanged: prove both initially absent and independently seeded present nonzero-gradient cases via an exact test-only observer/seed seam, without invoking E3 backward, VJP, graph capture or a production setter. The retained `tests/e3_private/retention_driver.esk:8–11,61–112` native snapshots already illustrate real parameter/gradient-word and metadata observation; any reuse requires its own exact tuple inventory and source review.

E3 failure/retry claims are separate from model-load preflight. Preserve §9's six-output/cursor/modes/parameter+gradient/RNG/owner rollback across the actual E3 allocation, copy, pin, provider-preflight, D2 read and final-metric boundaries. Inject only before/after a completed validated provider call; keep K1's nonfailing invoke contract. A fixture-control failure is not an E3 rollback witness.

## Review gate

Before code, review the exact noninstalled constructor/bridge entry, payload encoder, rooted sealed-model lifetime, source/destination cleanup, the prepare-result unwrapping and the complete postprepare generated AOT path. Place fault cuts only before native prepare or after the completed commit. Then run source-closure/topology/import tests, focused I2 full-batch/negative tests, independent oracle generation, and the supported normal/sanitized AOT numerical gate with pinned runtime/compiler inventories and retained real transcript. Until that gate passes, this contract establishes feasibility only; it does not satisfy the missing §9 rows, imply public E3 API availability, or waive unreachable direct-provider-only cases.
