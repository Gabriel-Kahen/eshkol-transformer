# D2 invocation-owned fault escape (source candidate)

The independently reviewed compiled direct-D2 fault/control diagnostic at `8fec18f` measured fault-only +2,288 shared-root arena bytes after a read failure, persistent through retry. The independently reviewed `2e941bb` mapper diagnostic repeated +2,288 for direct and mapped D2 faults, with flat controls. Its adjacent mapper samples were equal inside the active region. Separately, the complete-E3 fault measured +2,360; the 72-byte difference is unattributed. These receipts establish persistent fault-path growth, not the size or identity of any promoted object.

`d2-with-shard-region` closes a shard region while keeping `caught`, then stores the promoted graph in an escape vector. The old vector was `state[11]`, allocated with the dataset. Pinned fe9 `runtime_regions.cpp` write-barrier semantics promote younger values to a destination's owner, so this store gives the caught graph dataset/root lifetime. This is a concrete avoidable ownership edge. The candidate instead returns a two-slot fault envelope only after `region-close` restores the enclosing caller arena. Packed and unpacked success paths allocate no new envelope. The `region-close region caught` keep, typed exact-read error constructor, raised error value, native batch cleanup, cursor commit and live-batch state are preserved; the success branch adds only a nonallocating envelope predicate. `state[11]` remains an empty private compatibility slot, and the test-only mapper probe checks that it does not retain a fault.

This is **source evidence only**. Pinned hosted `raise` also allocates an exception header and message in the shared root arena. The candidate may remove only some of the measured +2,288 bytes; no flat-root or complete-call retention claim follows. Its host tests check both row paths and the fault-only allocation branch, reject four restored root-escape or success-allocation regressions, compare the typed-error, cleanup and cursor seams with the predecessor and check region-close-before-envelope order, and retain fresh-process fault/control checks. They do not execute compiled Eshkol.

The next gate requires independent source review, fresh exact private package/import/AOT custody, paired direct-D2 and mapped-D2 fault/control under normal A/B, poison and sanitizer, then full-E3 fault/control and the original complete-call retention assertion. Verify typed category, operation, source domain/code/errno, cursor, no live D2 batch/borrow, model/owner state and same-authority retry. Any residual root delta requires a new causal repair, potentially in upstream raise handling, before admission.
