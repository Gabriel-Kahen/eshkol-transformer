# Trained C4 checkpoint and history continuation: next dependencies

**Source anchor `59670d39`/tree `226fdb44`; this note adds no API or runtime
admission.** The accepted context-two trained C2 SAVE, reader, same-registry
replay and fresh-process P1/G1 comparison culminate in consumer branch
`9659c148` and run SHA-256
`a1407b14da03523b019165a1d6eae92f416fa00280122e44aba8c7669f092b70`.
They cannot supply a context-four trained model or a
four-position generation history. The C4 P2/G2 terminal fixtures use the

## Authorities already present

- `native/g3c4_model_extension.esk` has one C4 registry, fourteen distinct
  primary handles, a tied token-embedding/head handle and a `[4,4]` position
  weight. `native/g3c4_trainable_constructor_extension.esk` and the P1/I2
  train-prepare sibling specify a tagged trainable entry in that registry.
  Train-prepare normal/repeat/sanitizer is accepted at `883cc8d6` (SAN run
  `f6cf28a7...`). Constructor v3 remains nonaccepting pending a marker
  repair; neither a compiled trainable model nor a workspace is admitted.
- The accepted C4 provider has a fixed four-token forward schedule. Individual
  position, residual, GELU, linear, LayerNorm and head-layout VJP leaves have
  bounded evidence. Causal-attention VJP `38c3ff7c` is also accepted (run
  `8a43a5f7...`, independent review `09d4a732...`). Individual kernels do
  not create a composed gradient graph.
- C2/K2 can store `[4,4]` and the other fixed C4 parameter shapes. The
  trained-C2 consumer proves 14 live bits and one P1/G1 trace after fresh
  restore, but its `G3RCV1` record has two history slots and `max_new<=1`.

## Ordered gates to the requested witness

1. Compile and independently admit the tagged constructor
   with its exact X1/T1/initializer/native-owner authority, RNG transition,
   rollback cuts and seeded feature-off control. Add a separately reviewed
   **read-only P1 topology authority** under source contract `af648efe`.
   It must prove the exact current P1 handle shells map to the native owner's
   fourteen bound identities; the constructor's one-time bind is insufficient.
   Calling `module-parameters` would commit an observation, so it is not that
   API. A later lease/active-workspace exclusion and storage-nonoverlap gate
   must be reviewed before allocation; the current TR3 lease predicate does
   not cover a future C4 trainer.
2. After those topology, association and exclusion gates, the smallest next implementation leaf is a
   **private C4 workspace create/reset/release and owner-binding contract**:
   one live trainable C4 entry and its existing native owner, exact fourteen
   ordered CPU-f32 handles and tied alias, fixed context-four input shape,
   one active-workspace edge, and atomic cleanup on each failure. It must
   return an owned workspace or typed status without a second model registry,
   copied seeded owner, provider call or gradient claim. Its shape/lifetime
   table and feature-off proof require review before implementation; no
   workspace allocation API is currently accepted for C4.
3. Bind that workspace to the genuine four-token forward provider, then
   compose every VJP in reverse order, including token embedding and
   causal attention. Specify every intermediate and gradient shape, alias
   boundary and failure cut; check central finite differences through the
   complete provider and position rows 2 and 3. Existing M3T workspace
   operations and L3S masked loss are fixed to two tokens and cannot be
   relabeled as four-token training. Add a reviewed four-token loss/seed route.
4. Extend D2 sequence choice, TR3 factory/step/eval and O2 integration for
   that **same trainable C4 owner**. Require a nonzero update, pre/post
   parameter and loss observations, fourteen parameter carriers, 28
   shape-matched moments, scheduler, X1 RNG, tokenizer, D2 cursor, config and
   token count. SAVE authentic C2 bytes; fresh LOAD must rebuild a live C4
   receiver in its own registry and compare every bit and tied identity.
   `native/cli3_b_extension.esk`, `native/m3t_transport_extension.esk` and
   `native/tr3_c_private_factory_extension.esk` currently require context two.
5. Admit private P2/G2 generation against that restored **trainable** owner
   after in-place eval transition and handle/provider reauthentication. The
   seeded terminal path, including first/second EOS, remains a control;
   Eshkol same-call terminal close and trained-owner binding need their own
   compiled proof. Compare IDs, raw bytes, 256 logits, K/V, masks, lengths
   and all four RNG words to independent references.
6. Define a distinct versioned/checksummed C4 companion: at least four
   ordered history IDs, prompt/generated/manual partition, exact policy,
   tokenizer and full C2 digest, and four RNG words. `G3RCV1` must reject it.
   Capture only committed same-owner history; fresh-process replay must
   reconstruct cache/logits with zero sampling draws, then continue from the
   same trained C2 and compare uninterrupted IDs, EOS and successor state.

A P2/G2 witness covers at most two generated tokens and second-token EOS.
General repeated decoding and later EOS require another admitted profile.
Each compiled runtime gate above needs source review, pinned normal/repeat/
native sanitizer receipts and retained negative controls before its claim
advances.
