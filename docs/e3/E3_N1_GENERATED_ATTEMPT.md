# E3 N1 generated finite-attempt sequencing diagnostic

Status: **same-UID source diagnostic; all authority and §9 gates HOLD**.
`tests/e3_private/e3_n1_generated_attempt.py` accepts no source path or
real-read mode. `probe(fault=None)` generates a fixed byte string and always
returns `status=HOLD`, `protected_pre_read_custody=HOLD`,
`resource_proof=HOLD` and `source_opened=false`. It neither opens OCI/Docker
data nor changes `CAPTURE_RUN_ENABLED = False` or
`REVIEWED_CAPTURE_SHA256 = None`.

## Exercised finite graph and contract

The caller forks one finite setup worker and obtains its final `wait4` peak.
That worker forks finite `broker`, `reader` and `sealer` children and records
each child's final `wait4` peak and exit status. Before forking the reader,
the broker writes and fsyncs a generated `HOLD.json`, fsyncs its parent
directory, reads the record back, and sends a `HOLD` pipe acknowledgment. The
reader then sends only fixed generated bytes to the broker. The broker checks
the stream against those bytes, then writes and syncs generated stage,
unsigned receipt and commit
stubs before sending `RECEIPT`. The sealer checks predecessor files and
writes and syncs an unsigned seal stub before sending `SEAL`. The setup
worker checks broker/sealer phase-pipe EOF, reaps the fixed roles and exits.

Each generated record pins a parent directory fd by walking every ancestor
from `/` with `O_DIRECTORY|O_NOFOLLOW`. File creation, directory sync,
readback and final-name checks use that fd; readback also uses `O_NOFOLLOW`
and checks the created inode and bytes. The public parent path is walked
again before and after readback and must still name the pinned directory.
An ancestor symlink or rename detected at those checks, or a same-byte file
replacement, remains HOLD. These are observations at the checked moments:
same-UID control can still change the path later or race the walks, so this
does not establish protected custody.

The outer observer records one `CLOCK_BOOTTIME` interval from before setup
fork through setup reap, report EOF, local report validation and peak-sum
calculation. The timestamp is taken immediately before the result
returns; that final assignment and the observer's exit are outside the
interval. The diagnostic also records the sum of observed setup and role
peaks. It uses a temporary same-UID directory and removes it after the
generated attempt; the records are **not protected custody**.

`probe(fault)` accepts only `before_hold`, `after_hold`, `after_receipt`,
`after_seal`, `hold_sync`, `receipt_sync`, `seal_sync`, `timeout`,
`inherited_fd`, and `cgroup_migration`. Sync faults cut a generated record
before its **file** fsync and prevent its acknowledgment; directory-sync,
readback and return cuts are not injected here. The injected extra broker
fd is detected and rejected before HOLD. `cgroup_migration` injects a mismatched
**self-reported cgroup string** at seal time; it does not perform or deny a
real migration. Timeout requests termination and bounded reaping of known
children. If setup is not reaped, the observer signals its still-live process
group and waits at most one further second for its final peak. If setup is
already reaped but report EOF is missing, it returns closure-unverified HOLD
without signaling a reusable numeric process-group ID. An unlisted or
detached actor is not proven closed by this fixed graph.

The generated-only test is:

```sh
python3 -I -B -m unittest discover -s tests/e3_private -p 'test_n1_generated_attempt.py' -v
```

It checks the normal phase order, three role peaks, setup peak and aggregate
arithmetic. The `observed_peak_sum_bytes` diagnostic is emitted only when
the setup report names all three declared roles with zero exit codes, no
unresolved actor, and the exact HOLD/RECEIPT/SEAL phase sequence. A partial,
failed, or inconsistent report omits the sum so it cannot undercount the
declared graph; adversarial report tests cover missing and failed roles,
unresolved actors, and missing or duplicate phases. Each phase, sync,
timeout, fd and cgroup-report fault returns HOLD without a false completion
claim.

The setup report decoder rejects duplicate JSON object keys at every level,
including repeated role names and repeated peak fields. Such a report is
`setup-report-unverified` and emits no peak sum, even if the last duplicate
would otherwise make the decoded graph appear complete. Raw report tests
cover conflicting broker peaks, nested peak fields and top-level keys.

The generated-record test replaces a synced path with either a new file
containing identical bytes or a symlink before readback; both are rejected.
It also rejects an already-symlinked ancestor and a parent directory renamed
after sync with the old pathname replaced by a symlink or a new directory.
The elapsed-time test advances the observer clock during both valid and
malformed report parsing and requires that work to appear in the result.

The separate
[finite-closure diagnostic](E3_N1_F32_FINITE_CLOSURE_PROBE.md) exercises a
detached pipe holder, but its result cannot be merged into this graph as a
whole-attempt proof.

## Missing deployment gate

The setup report is same-UID and unauthenticated, so even a complete reported
sum is not a trustworthy whole-attempt RSS bound. The active outer observer
also has no final peak measurement and has not ceased at the diagnostic end
timestamp. Thus the longer interval is still not a completed-attempt time
proof. All actors run as the caller UID in its
existing cgroup. Pipes are not an
authenticated protected channel, the stubs have no v3 signatures or
protected stores, and the outer active observer's final RSS is not measured.
There is no spawn/migration denial, independently protected pre-read intent,
immutable handoff, complete raw source transport, actual receipt/seal
delivery, or closed hostile process graph. A forged cgroup report would not
prove membership. Even a small observed peak sum and elapsed interval cannot
establish the 268,435,456-byte current-RSS or 30-second completed-attempt
predicate. An unresolved worker or pipe is HOLD. The
[authority host gate](E3_N1_AUTHORITY_HOST_GATE.md) and
[protected attempt contract](E3_N1_F32_ATTEMPT_BOUNDARY.md) remain the next
dependencies; v3 provider/signing and real protected stores are still absent.
