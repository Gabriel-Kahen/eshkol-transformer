# G3-C4 Step 21A — private output ID staging

Status: isolated implementation candidate. This is not T1 decoding, text
acceptance, result publication, or a public generation API.

## Boundary and dependency

`ET_G3C4_OUTPUT_DECODE_IDS_PRIVATE` requires accepted Step20A numeric output
preparation. It adds one source-private call:

```c
int64_t et_g3c4_private_output_copy_decode_ids_v1(
    void *context, void *output, void *staging_header);
```

The staging pointer is the pinned Eshkol bytevector representation: an exact
signed-i64 native length header followed by `8G` payload bytes. Only `G=0` or
`G=1` is admitted. The function authenticates the active generation context,
its unique linked pending output, numeric readiness, unchanged text readiness,
and the committed parameter binding before inspecting the carrier.

## Copy and readiness

The complete carrier span must be valid and disjoint from every enrolled G3-C4
transport record, the model owner, all fourteen pinned parameter views, every
live I1 control/metadata/data/borrow allocation, and A2 cache/transaction
storage. The exact output I1 `[G]` is
borrowed synchronously. Its rank, shape, byte count, and generated byte ID are
validated before any caller byte is written.

For G0, the carrier declares length zero and no payload byte is touched. For
G1, the sole ID must be in `[0,255]` and is encoded explicitly as eight
little-endian bytes. The I1 borrow ends before the no-failure tail copies the
private eight-byte staging value and sets `ids_copied=1`. Repeated and
out-of-order calls reject before writes.

## Failure atomicity and proof

Tests cover G0/G1 success, use before numeric preparation, stale binding,
negative/short/long carrier lengths, NULL/overflowing spans, wrong-kind and cross-context owners,
context/output/model-parameter/cache/output-I1 and separate live-input-I1
aliases, active I1 borrows, the I1 borrow
allocation cut, and an adversarial out-of-range staged ID. Every failure leaves
the carrier, all output fields, committed binding/RNG, and ready token frame
unchanged; the same valid owner remains usable after recoverable failures.

Normal, repeated, and ASan/UBSan/LSan output must be byte-identical in the
supported Ubuntu 22.04 / LLVM 21.1.8 image. Object inspection must add exactly
the source-private staging symbol and its one source-private I1 storage-query
dependency.

## Limits

This leaf adds no T1 registry/core authentication, semantic raw-token decode,
raw text storage, `output_accept_text`, frame preparation or commit, cache/RNG
publication, live-output transition, accessor clone, EOS behavior, generation
loop, package export, installed symbol, or public generator.
